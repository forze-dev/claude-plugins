# temp/ — вхідна тека розробника

Сюди розробник кидає все сире, що прийшло від клієнта, **до** початку роботи.
Агент читає цю теку першою і розкладає вміст по місцях.

У git потрапляє лише цей файл; усе інше ігнорується (`temp/*` у `.gitignore`).
Тож сюди можна кидати важкі архіви й сотні фото, не засмічуючи репозиторій.

## Що сюди кладуть

- макети з Figma: експорт, скриншоти, посилання в текстовому файлі;
- бриф, ТЗ, приклади сайтів-орієнтирів;
- пакети зображень і медіа від клієнта — фото, логотипи, відео;
- набір фавіконів із генератора;
- будь-що інше, що ще не має свого місця в проєкті.

Структура всередині довільна — розкладати має агент, а не розробник.

## Що з цим робить агент

**1. Спочатку читає, потім питає.** Те, що є в `temp/`, замінює частину питань
під час брифу. Плагін `landing@forze` кладе сюди оригінали матеріалів клієнта
під час створення проєкту, а агент перевіряє цю теку першою.

**2. Розкладає медіа по місцях.** Зображення й інші статичні файли переїжджають
у `public/assets/`:

| Що | Куди |
| --- | --- |
| Фото для галерей, hero, контенту | `public/assets/images/` |
| Іконки SVG | `public/assets/icons/` |
| OG-зображення 1200×630 | `public/assets/seo/` |
| Фавікони | `public/` (у корінь, імена не змінювати) |

> **Ніколи не клади файли в `dist/`.** Ця тека генерується командою
> `npm run build` і повністю перезаписується при кожній збірці — усе, що туди
> покладено руками, зникне. `dist/assets/` — це просто копія
> `public/assets/`, зроблена під час збірки.

**3. Оптимізує, а не копіює наосліп.** Фото з телефона на 8 МБ не має їхати на
прод. Перед перенесенням: стиснути, привести до потрібних розмірів, за потреби
конвертувати у WebP. Якщо зображень багато — спитати, які саме потрібні, а не
тягнути всі.

**4. Дає осмислені імена.** `IMG_20260927_114532.jpg` стає
`workshop-interior.webp`. Імена латиницею, малими літерами, через дефіс.

**5. Не видаляє оригінали.** Після розкладання файли лишаються в `temp/` —
вони не в git і нікому не заважають. Видаляє їх розробник, коли вважає за
потрібне.

## Чого тут не буває

`.env` і будь-які доступи. Їм місце поза репозиторієм: локально — `.env` у корені
проєкту (він у `.gitignore`), на хостингу — рівнем вище за `public_html`. Тека `temp/`
ігнорується git-ом, але не є сховищем секретів.
