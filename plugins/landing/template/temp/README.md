# temp/ — incoming materials

Everything raw from the client goes here **before** work starts. The agent
reads this folder first and sorts its contents into place.

Only this file is tracked in git; everything else is ignored (`temp/*` in
`.gitignore`). So heavy archives and hundreds of photos can go here without
cluttering the repository.

## What goes here

- design mockups: Figma exports, screenshots, links in a text file;
- the brief, specs, example reference sites;
- the client's image and media packs — photos, logos, video;
- a favicon set from a generator;
- anything else that doesn't have its place in the project yet.

The structure inside is arbitrary — the agent sorts it, not the developer.

## What the agent does with it

**1. Read first, then ask.** What's in `temp/` replaces some of the brief
questions. The `landing@forze` plugin puts the client's original materials
here while creating the project, and the agent checks this folder first.

**2. Sorts media into place.** Images and other static files move to
`public/assets/`:

| What | Where |
| --- | --- |
| Photos for galleries, hero, content | `public/assets/images/` |
| SVG icons | `public/assets/icons/` |
| OG images 1200×630 | `public/assets/seo/` |
| Favicons | `public/` (root, keep the file names) |

> **Never put files into `dist/`.** It is generated by `npm run build` and
> overwritten entirely on every build — anything put there by hand disappears.
> `dist/assets/` is just a copy of `public/assets/` made during the build.

**3. Optimizes rather than copies blindly.** An 8 MB phone photo must not go to
production. Before moving: compress, resize to what's needed, convert to WebP
if appropriate. If there are many images — ask which ones are needed instead
of taking them all.

**4. Gives meaningful names.** `IMG_20260927_114532.jpg` becomes
`workshop-interior.webp`. Latin letters, lowercase, hyphenated.

**5. Doesn't delete originals.** After sorting, files stay in `temp/` — they
aren't in git and bother no one. The developer deletes them when they see fit.

## What never goes here

`.env` and any credentials. They belong outside the repository: locally — `.env`
at the project root (it's in `.gitignore`), on the hosting — one level above
`public_html`. `temp/` is git-ignored, but it is not a secrets store.
